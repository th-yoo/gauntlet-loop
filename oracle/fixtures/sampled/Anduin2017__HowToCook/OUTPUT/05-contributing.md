# Contributing New Recipes

This guide is meant to grow the way an open-source project grows: through
small, direct contributions rather than a single maintained backlog.

## Fixing something that's wrong

If a step is unclear, an ingredient is missing from a list, or a quantity is
vague where it could be exact, fix it directly and submit the change. Don't
file it as a problem for someone else to eventually get to — the whole point
of a precise, structured format is that gaps are visible and correctable in
place.

## Adding a new recipe

Every new recipe should follow the same template as the existing ones, so
that anyone browsing the index can rely on a consistent shape:

1. **Ingredients**, listed completely, before any step references them —
   with quantities wherever a real quantity is knowable, not "to taste"
   used as a way to avoid measuring.
2. **Steps**, numbered, in the order they're meant to be performed, with no
   step introducing an ingredient that wasn't in the list above.
3. **Difficulty and time estimate**, so a reader can decide whether a dish
   fits the time and skill they have right now, before starting it.
4. Notes on **substitutions or common failure points**, if any — the things
   an experienced cook would warn a first-timer about.

Copy the structure of an existing recipe in the same category as a starting
point rather than inventing a new format — consistency across entries is
what makes the index skimmable in the first place.
