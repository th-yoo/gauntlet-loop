# Connecting an AI Agent or MCP Client

Three separate paths exist for wiring an agent up to this service. They are
not interchangeable — pick based on what kind of client you're configuring.

## Path 1: Skill install (one command)

For agent tools that support the "skill" pattern (works with Claude Code,
Antigravity, and OpenCode, among others):

```bash
npx -y firecrawl-cli@latest init --all --browser
```

Restart the agent afterward for it to pick up the new skill.

## Path 2: MCP server config

For any MCP-compatible client, add a server entry:

```json
{
  "mcpServers": {
    "firecrawl-mcp": {
      "command": "npx",
      "args": ["-y", "firecrawl-mcp"],
      "env": {
        "FIRECRAWL_API_KEY": "fc-YOUR_API_KEY"
      }
    }
  }
}
```

This spawns `firecrawl-mcp` via `npx` and passes the API key through the
environment — no separate install step is needed beyond having `npx`
available.

## Path 3: Self-service onboarding for an agent with no key yet

If the agent itself needs to sign a user up and obtain a key before either
of the paths above will work, it fetches a skill document describing that
flow:

```bash
curl -s https://firecrawl.dev/agent-onboarding/SKILL.md
```

This is meant to be read and acted on by the agent, not a human — treat it
as bootstrapping when no `FIRECRAWL_API_KEY` exists yet.

## Picking one

| Situation | Path |
|---|---|
| Using Claude Code, Antigravity, OpenCode, or another skill-aware agent, and you already have a key | Path 1 |
| Using a generic MCP client (not skill-aware) | Path 2 |
| An agent needs a key and doesn't have one yet | Path 3, then Path 1 or 2 |

## Contributing new skills

If you're building or fixing a skill rather than just installing one, where
the change belongs depends on its kind:

- A skill that integrates this service into product/application code
  (build or SDK skill) → contribute it in this project's own `skills/`
  directory.
- A CLI skill, including research or developer-index skills → send it to
  the separate `cli` project instead.
- A workflow skill → send it to the separate `firecrawl-workflows` project.
- The public skills catalog is generated by CI from the sources above and
  is **read-only** — changes proposed directly against the catalog will not
  land; propose them against whichever of the three sources above actually
  owns that skill.
