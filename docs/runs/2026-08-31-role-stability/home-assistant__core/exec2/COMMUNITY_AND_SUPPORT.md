# Community and Support

## Who this project is for

The project names its builders directly: a worldwide community of tinkerers
and DIY enthusiasts. That framing matters for anyone deciding whether to
adopt open source home automation instead of a packaged commercial product —
support comes from peers who run the same software on the same kind of
hardware (a Raspberry Pi or a local server), not from a vendor's paid support
line.

## Where to ask for help

Two separate channels are named:

1. A chat community, for real-time discussion. Its existence is signaled by
   a live status indicator on the project's own introduction, which implies
   the chat is active enough to be worth advertising up front.
2. A dedicated help section on the project website, specifically pointed to
   for anyone who runs into issues either while using the system or while
   developing a component for it. Naming both "using" and "developing" as
   covered cases indicates the community supports contributors as well as
   end users, consistent with a project that invites outside developers to
   write their own components.

## Governance signal

The project identifies itself as a project from the Open Home Foundation
rather than from a single company. For a privacy-first, local-control
project, this is a relevant piece of context: it suggests the mission is
backed by an organizational structure oriented around that goal rather than
around a commercial cloud offering that the local-first software might
otherwise be expected to upsell toward.

## Practical takeaway

Someone adopting this project for home automation is not just adopting code;
per the project's own framing, they are joining a community that already
maintains chat and help channels, and that community — not a vendor support
contract — is the intended first stop when something goes wrong.
