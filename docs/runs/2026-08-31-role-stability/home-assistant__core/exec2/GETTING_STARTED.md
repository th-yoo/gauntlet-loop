# Getting Started

This guide summarizes the on-ramp for someone evaluating the project, built
strictly from what a short project introduction promises. It does not
reproduce content this document has no access to (specific installation
commands, specific supported devices, specific screenshots) — it only states
what such content is described as covering, so the reader knows what to look
for once they reach the primary sources.

## 1. Try it before installing it

A hosted demo is offered so a prospective user can see the system's state
views before committing to running it themselves. This matters for a
privacy-first project in particular: trying the demo does not require
installing anything on the user's own hardware.

## 2. Choose the hardware

The project is explicitly described as fitting on a Raspberry Pi or a local
server. That is the intended deployment shape — commodity, owner-controlled
hardware rather than a proprietary hub or a vendor cloud account.

## 3. Install

Dedicated installation instructions exist for setting the system up on that
hardware. This document does not restate their content because it draws only
on the introductory material, not the instructions themselves.

## 4. Learn the automation model

Tutorials exist specifically for building automations once the base system
is running. Automations are the mechanism by which "home automation" in the
mission statement becomes concrete: rules that react to state.

## 5. Add integrations

Because the system is modular, devices and services are added as separate
integrations rather than as changes to a monolithic core. A featured set of
integrations is highlighted by the project itself as a starting point for
what is possible, though the specific list is not part of what this document
was given to work from.

## 6. Reference documentation and architecture

Full documentation, plus a dedicated section on the system's architecture
and on writing new integrations, is available for anyone who wants to go
beyond using the defaults — including the DIY enthusiasts and tinkerers who
the project says power its development.

## 7. Get help

If installation or development runs into trouble, a help section is the
named place to go, backed by the same community described as building the
project.
