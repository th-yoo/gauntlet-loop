# Getting Help / Being a Good Contributor

## Asking for help

Do not email the maintainer directly for general or technical
questions — that channel is explicitly not staffed and will not get a
response.

Before asking anywhere, try searching a general search engine, the
project's issue tracker, or its subreddit; a lot of questions already
have answers there. If none of that turns anything up, open a
discussion in one of these two places instead:

- The project's issue tracker
- Its subreddit

The maintainer does watch the subreddit under a personal account and
can be mentioned directly there if you want their attention on a
question.

## Trying things before they're official

- A live demo instance exists (hosted in Frankfurt, Germany) for
  kicking the tires without installing anything. Any data you put into
  it is wiped after ten minutes, so treat it as throwaway.
- Beta releases are cut periodically if you want to try upcoming
  features before they reach a stable release.

## Contributing back

- **Pull requests** are welcome. Read the project's pull-request
  guidelines before opening one — reviews go faster when a PR already
  follows the house style described there.
- **Testing open pull requests** is also valuable help: there are more
  open PRs at any given time than the maintainer has bandwidth to test
  personally, and manually trying one out and reporting back is a real
  contribution even without writing code.
- **Bug reports and feature requests** belong in the issue tracker.
- **Translations**: if you want to help translate the interface into
  another language, follow the localization README maintained
  specifically for that purpose rather than sending translated strings
  ad hoc.
- **Spelling and grammar fixes** in the documentation or code are
  explicitly welcomed — the maintainer has said outright that English
  is not their first language and grammar slips are expected.

## Roadmap

Requests and issues the maintainer intends to act on get assigned to a
milestone; check the milestones list to see what's already been
triaged for upcoming work rather than re-requesting something that's
already queued.
