# 0001 — Who reads the coverage sweep

**Status:** decided, 2026-08-26. **Decided by:** the operator (th-yoo).
**Closes:** the fifth root cause of issue 46 — its option 4, *"neither, deliberately,
recorded as a decision, with the reason."*
**Ledger this rests on:** `docs/runs/2026-08-26-rc5-suspects.md` (17 suspects, walked as a
pipeline rather than a list).

## The question

`scripts/coverage-sweep.mjs` breaks each property a test is supposed to pin and reports
anything that does not fail. Issue 45 gave it a cadence. Nothing was decided about who
reads what it produces, and a red Monday nobody opens is the same coverage as no sweep.
Issue 46 offered four options — a README badge, failing on a surprising summary, posting
the summary where it will be read, or deciding deliberately to do none of them.

## What was measured before deciding

- **The signal has never fired.** Discounting three runs whose verdicts were masked by a
  defect since fixed at `3709cef`, no `NOT CAUGHT` has ever occurred in this repository.
  The only finding the sweep has ever produced was one `COULD NOT RUN` — a needle left
  stale by a rename.
- **The weekly cadence has never produced a run.** Every sweep run in the repository's
  history is push-triggered: 13 push, 0 schedule.
- **Every transport that existed had a success rate of zero, on three trials.** All three
  findings that have ever reached a person arrived inside a working session — a log opened
  by hand at the end of a long session, a question asked mid-session, an agent noticing
  while arguing something unrelated. None arrived via a run page.
- **Only one bit of a sweep result survives outside the run page**: the run's conclusion,
  queryable with `gh run list`. The rendered job summary is not fetchable — no REST
  endpoint returns it, the check-run output comes back empty, and the run page is a
  JavaScript shell. A badge, an e-mail and a run-page summary therefore cannot be verified
  by anything this repository runs.

## The decision

**The reader is the session-start hook, and nothing else is built.**

`scripts/sweep-status.mjs`, wired as a `SessionStart` hook in `.claude/settings.json`,
prints the last sweep's conclusion at the start of every session in this project. It was
chosen because it puts the one transportable bit where the attention measurably arrives,
it fires without being remembered, and a test in this repository can check that it is
wired at all.

Declined, with reasons:

- **A README badge.** Red-only, requires someone to open the repository page, and cannot
  be checked by anything here. Strictly weaker than the hook on every axis.
- **E-mail / notification settings.** Not a property of this repository, so nothing here
  can verify or maintain it. This repository has also never established which events
  GitHub e-mails for this account, and no argument above depends on that.
- **An auto-filed issue.** The only declined option that is genuinely stronger on two
  axes — it persists, and `gh` can query it. It is declined *for now* on cost against a
  base rate of zero, not on principle. See the revisit trigger.
- **Putting the sweep in `ci.yml` as a gate.** It would cost a full sweep per push, and it
  does not add a reader: a red CI run lands on the same Actions tab nobody opens. Nothing
  in this repository blocks in any case — main has no branch protection, no required
  status checks, and `.git/hooks` holds samples only.
- **A local pre-push gate.** Refused outright, and not on cost: the sweep mutates the tree
  it checks. In CI the checkout is ephemeral; in `.githooks/pre-push` it is the
  developer's own working tree, and a crash leaves the mutation behind. That was observed
  on 2026-08-26, when `skills/gauntlet-loop/loop.js` was found at zero bytes.

Two of issue 46's options had already landed and are kept: the sweep renders its summary
into `$GITHUB_STEP_SUMMARY` on clean runs as well as failures (`1d3e9b1`), and the property
count is compared against a live import rather than a hand-copied constant, on every push
(`coverage-cadence.test.mjs`).

## What this decision accepts, rather than solves

Named here so they are not rediscovered as new defects:

1. **A finding riding inside a green run is still invisible.** The exit code is the only
   thing that travels, so any future number in the sweep's output that nothing compares
   against anything will be unread while the run is green. That is the exact instance
   issue 46 was filed on — run `32900618692`, `success`, two defects in its log. The two
   findings from that run are now structurally impossible, the class is not.
9. **Nothing in the repository holds a sweep result.** Every verdict that has ever existed
   lives only on a GitHub run page and expires on GitHub's retention schedule. When an
   unread finding stops existing, so does the evidence that it existed.
3. **The transported bit is ambiguous.** `NOT CAUGHT` (a property nothing tests) and
   `COULD NOT RUN` (a needle went stale) need opposite repairs and share exit 1. The
   hook's red branch names both and says it cannot tell them apart, which is mitigation,
   not a fix.
4. **Whether anyone acts on the line the hook prints cannot be checked.** No mechanism
   here can measure attention. This decision moves the question from "nobody decided" to
   "the operator decided, and this is the reason" — which is all option 4 ever claimed to
   do.

## What would reopen this

- **The first genuine `NOT CAUGHT` in this repository's history.** Until one occurs, every
  argument above is about a transport for a package that has never been posted. When one
  occurs, persistence and an auto-filed issue become worth their cost immediately, because
  the base rate that declined them will no longer be zero.
- **A second person working in this repository.** A session-start hook reads to whoever
  starts a session in this project; it says nothing to a reviewer looking at a pull
  request. At that point the auto-filed issue is the right build.
- **The hook being removed.** `test/sweep-status.test.mjs` asserts that a `SessionStart`
  hook names an existing script, so removing it fails the suite rather than silently
  retiring this decision.

## What this decision does not establish

That the hook is read. That the sweep's list of properties is complete — it is
hand-written, and a property nobody listed produces no finding to transport, which is a
different question from this one. And exhaustiveness of the suspect ledger behind it: five
of its eight passes corrected a claim that had already been pushed.
