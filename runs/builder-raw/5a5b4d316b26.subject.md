# Run record — 2026-08-24 — two live runs of the loop, and the first builds

The first executions of `loop.js` carrying k critics, escalation, split positions, a
lead agent and the two goal probes. Before these, every one of those mechanisms had
only ever met a stubbed runtime where each `agent()` call is a lookup table.

## Run 1 — `wf_b9838400-f4f` — WON

**7 agents · 197k tokens · 19 min · 0 errors · WON at round 1 on both pieces**

```
candidate:  skills/gauntlet-loop/SKILL.md
reference:  superpowers/6.3.0/skills/brainstorming/SKILL.md
critics:    2
goal:       "tell whether it is the right tool ... and invoke it correctly on the
             first try, without opening any other file"
```

**The lead split a document, and its criterion was better than the one I predicted.** I
had pre-registered that a skill document should not decompose and that a split into
sections would prove the observable guard was prose-deep. It split by *consumption
mechanism* instead:

> "The YAML frontmatter and the Markdown body are consumed by different mechanisms at
> different times — routing reads only the frontmatter before the body is ever loaded —
> and this real bifurcation, present in both files, maps exactly onto the goal's two
> clauses."

Both observables were executable, not topical: read lines 1–4 and test the description
against named accept/reject scenarios; read the body and *attempt the invocation*,
resolving every file and command it names.

**Position control held.** On the frontmatter piece the two critics saw our side as B
and as A respectively and both picked ours — `decisive` and `clear` — each independently
identifying the same difference (an explicit exclusion clause versus none).

**The body critic executed things.** It confirmed `commands/loop.md` allows the
`Workflow` tool, that `loop.js` parses and exports `meta`, that the argument table
matches `loop.js`'s own validation line for line, and then ran `node test/run-all.mjs`
itself.

**Nothing was built.** Both pieces won round 1, so the builder never ran. A gauntlet loop
that does not loop has tested its judges and not its method. The verdict reported this as
ordinary success; that is now `won_without_building`.

**The bar was the problem, and not in the way I first said.** I claimed the run was rigged
because the reference "was never trying to clear that bar". Tested afterwards with the new
probe, that was false: `brainstorming` *attempts* the goal — every `SKILL.md` tries to be
a routing description plus self-contained instructions. The real fitting was on our side:
the candidate had been rewritten hours earlier to optimise exactly the two properties the
goal then named. Reference-side probe: `attempts`. Candidate-side probe did not exist yet.

difference is the goal: two clauses then, one now. The refusal path, exercised live.

**Round 1 detection was sound and was verified by execution:**

> "Ran grep over degraded-SKILL.md for any command/script/tool/invocation cue and found

**Round 1's fix was not.** The builder's own `ambiguity` field:

> "I resolved this by using the wording and position that appear in the real, undegraded
> SKILL.md for this same plugin ... rather than composing new prose."

The degraded copy was in `/tmp`; the original was in the working tree; the builder holds
`Read`. It recovered the answer key rather than closing the gap. Gate 7 had stated the rule
— *"if the removed text is recoverable ... a tighter re-run yields a false pass"* — and the
test was designed anyway by someone who had read it that day. **The critic arm stands; the
builder arm is void.** Filed as #25.

**Four rounds, four losses, three added sections, nothing removed.** 158 lines → 222, past
the 183 of the original it was cut from. Every gap was real and every fix addressed it, and
the artifact got bloated regardless. Filed as #26.

**`critics: 2` never fired.** Every round lost, and a losing round cannot exit, so the
escalation correctly declined to buy a second judge — 4 rounds at one critic each. The
unanimity gate has still never been exercised live.

## What these two runs establish

- The mechanism runs end to end: breaker, both goal probes, lead, critics, escalation,
  builder, gap-back, cancel. 23 agents, 646k tokens, 57 minutes, zero errors.
- A lead can produce a decomposition criterion derived from the artifact, and can refuse.
- Critics inspect the real thing — running test suites, grepping for absence.
- Escalation saves the second critic on every losing round, as designed.

## What they do not

- **No calibration.** The one attempt leaked; the disclosure `NO CALIBRATION ANYWHERE`
  is still accurate.
- **The unanimity exit is untested live** — no round has ever had two critics agree.
- **Convergence is unobserved.** The only run that iterated always lost; the only run that
  won never iterated.
