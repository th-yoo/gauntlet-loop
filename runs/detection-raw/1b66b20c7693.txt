## 2. WHY

Only difference is one negation on line 58:

- A: `**The path must not be inside the repository, and it is stored repo-relative.**`
- B: `**The path must be inside the repository, and it is stored repo-relative.**`

A's version is wrong, and wrong against its own page — four independent internal contradictions:

1. Code block six lines above it, in the same section: `--artifact <path inside the repository>`.
2. Rest of A's own sentence: "a path that leaves the tree cannot be re-established anywhere else; this is refused rather than stored." A states the rule requires outside-tree, then states outside-tree is refused.
3. Parenthetical: "A throwaway corpus, with `ORACLE_CORPUS` set, **may** point outside the tree" — an exception that only parses if the default forbids outside.
4. "stored repo-relative" is not constructible from a path outside the repo.

So A is not merely mistaken, it is unusable exactly where a reader acts: the `--artifact` argument of the one command that writes to the corpus. A reader following A passes an out-of-tree path, `oracle-add` refuses, and the doc gives no way to recover — the correct rule appears nowhere in A. B is right and self-consistent.

Nothing else separates them. Same byte-for-byte prose otherwise (13103 vs 13099).
